# SLIDE 7 — WORKFLOW / HOW IT WORKS

## Title

**From Gesture to Action in Milliseconds**

Explain the complete workflow.

### Step 1

**Trigger**

User holds the configured trigger key.

↓

### Step 2

**Draw**

User draws the gesture using the mouse.

↓

### Step 3

**Recognize**

The gesture recognition system identifies the pattern.

↓

### Step 4

**Context**

The system checks the active application and associated gesture configuration.

↓

### Step 5

**Map**

The gesture is mapped to its configured command or command sequence.

↓

### Step 6

**Execute**

The action is executed immediately.

→ Recognize Slash

→ Open Terminal

# PRESENTATION DESIGN RULES

Follow these rules across all 10 slides:

### 1. Visual Style

Use a **premium minimal technology aesthetic**.

Think:

**Apple product presentation + modern developer tool + clean productivity software**

rather than:

**Cyberpunk + futuristic AI + gaming UI.**

### 2. Colors

Use approximately:

* 70% neutral background
* 20% dark text / UI elements
* 10% accent color

Use one primary accent consistently.

### 3. Typography

Use a modern sans-serif font.

Titles should be bold and large.

Body text should be short and highly readable.

Avoid paragraphs longer than 2–3 lines.

### 4. Visual Language

Use:

* Mouse cursor
* Gesture trails
* Application windows
* Minimal code snippets
* Command symbols
* Keyboard keys
* Clean diagrams
* Workflow arrows
* Subtle grids

Avoid:

* Robots
* Human brains
* Generic AI imagery
* Excessive circuit-board backgrounds
* Random technology stock photos
* Overly glowing interfaces

### 5. Animations

If animation is supported, use subtle animations:

* Gesture path drawing
* Cursor movement
* Command cards appearing
* Pipeline stages activating sequentially
* Smooth application-card transitions

Avoid flashy transitions.

### 6. Content Rule

Every slide must answer **one question**.

Do not fill empty space just to make the slide look busy.

Use visuals to explain concepts instead of adding more text.

### 7. Presentation Tone

The presentation should communicate:

**"This is a practical, lightweight productivity tool."**

Not:

**"This is another complicated AI project."**

### 8. Overall Story

The presentation should flow naturally:

**Hook**

↓

**Idea**

↓

**Problem**

↓

**Solution**

↓

**Differentiation**

↓

**Workflow**

↓

**Capabilities / Demo**

↓

**Technical Strength**

↓

**Future**

↓

**Conclusion**

The audience should understand the project even if they have **zero prior knowledge of mouse gesture recognition**.

The final impression should be:

> **Simple interaction. Powerful execution. Lightweight technology.**
